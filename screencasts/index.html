Traditional tools assignment

MuseScore Drumline Basics

Entering a short drumline phrase with MuseScore’s regular interface.

Runtime: 2:44Traditional software walkthrough

Script

[Show the full score with the Palettes panel open on the left.]

“Let’s enter a simple drumline part using MuseScore’s regular interface.

[Outline the Palettes panel on the left.]

First, open the Palettes panel on the left. We’ll use Note Input for rhythms, Articulations for accents, and Text for sticking.

[Outline the first measure on the snare staff. Point to the N key or note input button.]

Click the first measure and press N to start note input. Choose a note value from the toolbar, or use the number keys: 5 for quarter notes, 4 for eighth notes, and 3 for sixteenth notes.

[Outline the note value buttons in the toolbar.]

Click the staff to enter each note. Press 0 to enter a rest with the selected duration. Press N again to finish.

[Show a note being entered, then point to the percussion staff positions.]

For percussion, staff position and notehead shape depend on the instrument’s percussion map. If a note appears in the wrong place or plays the wrong sound, check the percussion note controls or the instrument’s mapping.

[Outline the Articulations palette and point to the accent marking.]

To add an accent, select a note, open the Articulations palette, and choose the accent. The same palette includes other markings, such as staccato.

[Outline the Text palette, then show an R or L placed above a note.]

To add sticking, select a note and use Text to place an R or L above it. Continue through the phrase, following your sticking pattern. Drag the text into position if needed.

[Outline the playback controls, then start playback.]

Press Space to play the score. Listen for the rhythm, and check that the sticking and accents are easy to read.

[Show the completed phrase.]

That’s the basic process: enter the rhythm, add articulations and sticking, then play it back.”

AI-generated assignment

Meet Claude Code

A look at how Anthropic’s AI coding assistant fits into a developer’s workflow, what learners can gain from it, and why human review still matters.

Runtime: 2:04Narration and on-screen captions

What you’ll see

Claude Code in the VS Code interface, with examples of code context, prompts, and reviewing proposed edits.

Learning perspective

How AI coding support can help learners explore code and debugging while keeping verification and independent thinking in the loop.

Reflection

AI apps can make educational video development feel more manageable. They can help with a first script, narration, captions, or visual ideas, which is useful if a teacher does not have a production crew or hours to learn editing software. A video also gives students a way to pause and replay an explanation when they need it. I can see why that would help with a topic that is easier to understand after watching an example more than once.

There is a catch: a video can look finished and still be wrong. Generated visuals might show a process inaccurately, and generated narration can mispronounce a term or sound strange. For my Claude Code screencast, the application itself needed to be visible because the point was to explain an actual AI coding tool. An invented screen or made-up button would have defeated the purpose. AI can help make the explanation, but the person making the video still has to check that the screen, words, and claims match the real application.

I also think these tools can be helpful when a lesson needs another version, such as a shorter explanation or captions, but that does not mean every student will learn from the same format. A video should give them a clear example to think about, not just something polished to watch. There are other concerns too: generated material can carry errors or bias, and imitating someone’s voice or style raises questions about consent. For me, the useful part is getting a draft or production help faster. The downside is that I have to spend time reviewing and correcting it, and I should be clear about what is synthetic. I would use AI as assistance, then make the final decisions myself.

That extra review is part of the work, not a reason to skip it. If I cannot explain why a generated example is accurate, I should not put it in a lesson just because it looks good.

Reflection: the two methods

The MuseScore video felt like a regular screencast: I had the score open and could show the controls as I talked about them. I planned it around one short drumline phrase, starting with the Palettes panel, entering notes, adding accents and sticking, and playing the result. The script’s bracketed directions reminded me what to show while narrating. That kind of recording takes preparation, but the viewer can see the real menus and follow the same path in MuseScore.

The Claude Code assignment was different because the focus was AI video production and the subject was an AI coding application. I still wanted the actual Claude Code interface on screen. That made the video feel tied to a real tool instead of a general description of AI. The production could use AI assistance, but I still had to make sure the material and explanation fit the application. A generated scene might be quick to make, but it would not help if it showed a feature that was not there.

Making the two videos made the tradeoff clearer to me. With MuseScore, I controlled what appeared by recording the actual workflow, though I had to plan the sequence and keep the narration in time with the screen. AI-assisted production can save effort on parts of making a video and makes it easier to try ideas, but I would need to check the result carefully. It can be hard to notice a wrong detail when the video looks convincing.

If I made another one, I would pick the method based on what the learner needs to see. For a lesson about using a particular program, I would record the real interface and explain each action. AI tools could still help me organize the script or captions, but I would verify them against the application. For a topic that benefits from illustrative visuals or a quick draft, I would try more AI assistance and review the finished piece closely. Neither process removes the work of deciding what the learner should take away. The traditional recording made the software steps easy to follow; the AI assignment made me think harder about which parts of production can be handed off and which still need my judgment.
