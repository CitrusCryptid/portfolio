Traditional tools assignment

MuseScore Drumline Basics

Entering a short drumline phrase with MuseScore’s regular interface.

Runtime: 2:44Traditional software walkthrough

Script

[Show the full score with the Palettes panel open on the left.]

“Let’s enter a simple drumline part using MuseScore’s regular interface.

[Outline the Palettes panel on the left.]

First, open the Palettes panel on the left. We’ll use Note Input for rhythms, Articulations for accents, and Text for sticking.

[Outline the first measure on the snare staff. Point to the N key or note input button.]

Click the first measure and press N to start note input. Choose a note value from the toolbar, or use the number keys: 5 for quarter notes, 4 for eighth notes, and 3 for sixteenth notes.

[Outline the note value buttons in the toolbar.]

Click the staff to enter each note. Press 0 to enter a rest with the selected duration. Press N again to finish.

[Show a note being entered, then point to the percussion staff positions.]

For percussion, staff position and notehead shape depend on the instrument’s percussion map. If a note appears in the wrong place or plays the wrong sound, check the percussion note controls or the instrument’s mapping.

[Outline the Articulations palette and point to the accent marking.]

To add an accent, select a note, open the Articulations palette, and choose the accent. The same palette includes other markings, such as staccato.

[Outline the Text palette, then show an R or L placed above a note.]

To add sticking, select a note and use Text to place an R or L above it. Continue through the phrase, following your sticking pattern. Drag the text into position if needed.

[Outline the playback controls, then start playback.]

Press Space to play the score. Listen for the rhythm, and check that the sticking and accents are easy to read.

[Show the completed phrase.]

That’s the basic process: enter the rhythm, add articulations and sticking, then play it back.”

AI-generated assignment

Meet Claude Code

What you’ll see

Claude Code in the VS Code interface, with examples of code context, prompts, and reviewing proposed edits.

Learning perspective

How AI coding support can help learners explore code and debugging while keeping verification and independent thinking in the loop.

Reflection

AI apps can make educational video development more accessible. A teacher can use them to draft a script, generate narration, create captions, or try different visual explanations without needing a full production team. That can leave more time for deciding what students actually need to understand. Videos can also be adapted for different reading levels or languages, and learners can pause, replay, or revisit a difficult idea at their own pace.

The benefit depends on the choices behind the video. AI-generated visuals can make an abstract process easier to picture, but a polished scene is not automatically an accurate one. In a video about Claude Code, for example, showing real interface screens helps connect the explanation to the tool students might use. If generated footage invents buttons, changes how a feature works, or makes a task look simpler than it is, it can teach the wrong thing.

AI video tools can save time and lower the barrier to making learning materials, but they also bring risks. Generated narration may sound unnatural, visuals can include errors or bias, and synthetic content can blur the line between a real demonstration and an illustration. There are also questions about copyright and consent when models imitate a person’s voice or style. I think AI-generated video works best as a starting point: educators should check facts, label synthetic elements when needed, and make sure the video supports active learning rather than replacing it. The goal is still for students to understand the subject, not just watch something convincing.

Claude Code interface imagery is from Anthropic’s official documentation.

Reflection: the two methods

Working on the MuseScore screencast felt familiar because I could show the real program and explain each action as it happened. I had to plan the order, capture the screen, and make the narration match what was visible, but I knew exactly what the audience would see. That matters with music software: a learner can follow the Palettes, note entry, and playback controls directly instead of trusting an invented interface.

The Claude Code video took a different route. AI helped create the narration and visuals quickly, so I could get from an idea to a finished piece without recording every part myself. That saved time, but I had less control over the details. Generated material can look convincing while still missing how the tool really works, so it needs review.

For me, traditional screen recording takes more hands-on work but feels dependable when the lesson is about a specific tool. AI generation is useful when speed or creative flexibility matters, though it adds extra checking and editing. I don’t think one replaces the other. I’d use the real interface to teach precise steps and bring in AI when it helps explain an idea or make a production task more manageable.
