Project Overview

This is my AI-powered version of the instrument-sorting activity, alongside the separate page where I adapted the course’s original drag-and-drop template. Here, the activity sorts instruments into brass, woodwind, and percussion families. Each round selects four instruments from each family, mixes the twelve choices, and asks the learner to place them in a group. The list changes when the activity is reset, so a learner gets a different set to work through instead of seeing the same fixed order every time.

I wanted the sorting itself to be easy to understand. The instructions say to drag an instrument into its family, and each group shows how many of its four instruments have been sorted. A correct choice moves into the group and adds to the correct count. A wrong choice gives a short message and adds to the misses, but leaves the instrument available to try again. When all twelve are sorted, the activity reports whether it was a perfect round or how many misses there were. Those responses make the result visible while the learner is working, rather than only showing a score at the end.

The activity also supports tapping an instrument and then tapping a family, which is useful on a touch screen and gives an alternative to dragging. That detail matters because a drag interaction can be awkward on some devices. Building a second version made me think about what should stay the same when the activity changes: the learner still needs to recognize the instrument names, understand the family categories, and get a clear response after each choice. I wanted this version to feel like a small, usable quiz rather than a page of code demonstrating a drag effect. Having the course-template adaptation beside it also makes it easier to compare the two approaches: one involved repairing and restyling an existing activity, while this one presents the same broad sorting idea through a different interface.
