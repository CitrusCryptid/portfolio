Project Overview

I started with the quiz template provided for the course, rather than building a quiz from scratch. I used VS Code because it is what I already know from game and web development. I changed the questions to make a ten-question quiz about gibbons and primates, added a gibbon background, and shifted the colors toward greens and other earthy tones. I also made the text and boxes larger. On my 13-inch MacBook Air, the example felt small enough that I had to squint, so I wanted the finished quiz to be easier to read on that screen.

The first time I opened the example, I thought I was supposed to type my answer into the solution box. I had missed the dropdown completely. I tried replacing it with multiple-choice radio buttons and moving the solution field down, but that broke the question display. I had to undo the field change; I kept the radio buttons and adjusted the JavaScript around them. I also noticed that it was possible to move to the next question without choosing an answer. I changed the response check so it returns null when nothing is selected, and the next question does not display until the learner picks an option.

I wanted an answer to lock after submission so the same question could not be answered over and over. That took a million tries. I asked Claude what I was missing, and it pointed me to the generatequestions() function: I had forgotten to tell the radio buttons to lock there. After adding that, I checked that the answer stayed saved when moving between questions and that the controls locked after a response. This was a good reminder that changing a form is tied to the code that fills it in. I was most familiar with the visual edits, but the small JavaScript details were what made the quiz behave the way I wanted. I may keep working on it as a portfolio project later.
